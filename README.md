# خودروتو

موتور جست‌وجو و تحلیل آگهی خودرو با رابط فارسی، راست‌چین و فونت **راوی**.

## اتصال زنده دیوار

اتصال پیش‌فرض پروژه بدون API Key و با endpointهای عمومی خواندنی فعلی وب دیوار انجام می‌شود؛ همان endpointهایی که وب‌اپ خود دیوار برای نمایش جست‌وجو و جزئیات آگهی استفاده می‌کند:

```text
POST https://api.divar.ir/v8/postlist/w/search
GET  https://api.divar.ir/v8/posts-v2/web/{token}
```

پیاده‌سازی بر اساس ساختارهای به‌روز پروژه‌های `divar-mcp` و `hydra-sender` انجام شده است. مسیر قدیمی `v8/web-search` دیگر مسیر اصلی پروژه نیست.

### قابلیت‌های اتصال

- جست‌وجوی بدون کلید آگهی‌های خودرو
- دنبال‌کردن cursor صفحه‌بندی تا پایان نتایج دسته (حداکثر ایمنی پیش‌فرض: ۵۰۰ صفحه)
- حذف آگهی‌های تکراری براساس token
- دریافت جزئیات و تصویر آگهی‌های برتر
- استخراج قیمت، شهر، محله، کارکرد، سال و رنگ
- فیلتر سمت دیوار برای دسته، عبارت جست‌وجو و بازه قیمت
- کش ۱۰ دقیقه‌ای، به‌روزرسانی خودکار پس‌زمینه و ادغام درخواست‌های هم‌زمان
- حذف آگهی‌های بدون قیمت و قیمت‌های مشکوک
- لینک مستقیم هر نتیجه به آگهی دیوار
- fallback شفاف به داده نمونه فقط هنگام خطای شبکه

## تنظیمات

```bash
cp .env.example .env
npm install
npm test
npm run dev
```

تنظیمات پیش‌فرض:

```dotenv
DIVAR_PROVIDER=web
DIVAR_CITY_IDS=1
DIVAR_WEB_CATEGORY=light
DIVAR_MAX_PAGES=0
DIVAR_HARD_MAX_PAGES=500
DIVAR_REQUEST_DELAY_MS=450
DIVAR_CACHE_TTL_MINUTES=10
DIVAR_API_BASE_URL=https://api.divar.ir
```

`DIVAR_CITY_IDS=1` شهر تهران و `light` دسته خودروهای سبک دیوار است.

### سرور خارج از ایران

دیوار ممکن است اتصال TLS بعضی دیتاسنترهای خارج از ایران را پیش از پاسخ HTTP قطع کند. تغییر DNS این محدودیت شبکه را حل نمی‌کند، چون DNS به‌درستی به IPهای دیوار resolve می‌شود و قطع ارتباط بعد از TCP و هنگام TLS رخ می‌دهد. برای استقرار خارجی می‌توان `DIVAR_API_BASE_URL` را روی یک reverse proxy مورداعتماد و تحت کنترل خودتان در یک سرور ایرانی تنظیم کرد:

```dotenv
DIVAR_API_BASE_URL=https://your-iran-proxy.example.com
```

از پراکسی عمومی ناشناس استفاده نکنید. سرور داخل ایران معمولاً می‌تواند مقدار پیش‌فرض مستقیم را استفاده کند.

## اتصال رسمی اختیاری کنار دیوار

آداپتور رسمی نیز حفظ شده است. برای استفاده:

```dotenv
DIVAR_PROVIDER=kenar
KENAR_API_KEY=your-server-side-key
DIVAR_CITY=tehran
DIVAR_CATEGORY=light
```

کلید فقط سمت سرور در هدر `x-api-key` فرستاده می‌شود. با این حالت endpointهای رسمی زیر استفاده می‌شوند:

```text
POST https://open-api.divar.ir/v2/open-platform/finder/post
GET  https://open-api.divar.ir/v1/open-platform/finder/post/{token}
```

## روش امتیازدهی

موتور تحلیل با میانه، MAD و Robust Z-Score قیمت هر آگهی را با گروه مشابه مقایسه می‌کند و امتیاز را با توجه به تازگی، کامل‌بودن اطلاعات، تعداد نمونه، سال، کارکرد و نوع وسیله تنظیم می‌کند. قیمت‌های بسیار پایین یا بالا، قیمت اقساط/پیش‌پرداخت و مشخصات غیرمنطقی با دلیل ریسک علامت‌گذاری می‌شوند و امتیاز آگهی مشکوک سقف می‌خورد. آگهی بدون تصویر وارد تحلیل عمومی نمی‌شود.

این امتیاز تضمین سلامت یا قیمت خودرو نیست و پیش از معامله باید اصالت آگهی، اسناد و سلامت خودرو مستقلاً بررسی شود.

## مدیریت درگاه‌ها و پنل‌های پیامکی

در تب تنظیمات مدیریت می‌توان بدون محدودیت تعداد، چند درگاه پرداخت و چند پنل پیامکی را ثبت، ویرایش، اولویت‌بندی، فعال یا غیرفعال کرد. کلیدهای محرمانه با AES-256-GCM رمز می‌شوند و هرگز در پاسخ API برگردانده نمی‌شوند. در production تنظیم `CREDENTIALS_ENCRYPTION_KEY` الزامی است.

```text
GET|POST       /api/admin/integrations/payment
PATCH|DELETE   /api/admin/integrations/payment/:id
GET|POST       /api/admin/integrations/sms
PATCH|DELETE   /api/admin/integrations/sms/:id
GET             /api/payment/options
```

فعال‌بودن هم‌زمان چند اتصال مجاز است و `priority` ترتیب ترجیح را مشخص می‌کند. اتصال واقعی به endpoint تراکنش هر شرکت، نیازمند adapter سمت سرور همان ارائه‌دهنده و اعتبارنامه معتبر اپراتور است.

## مرکز مدیریت و محتوای صفحه اصلی

پنل فارسی مدیریت شامل مرکز فرمان و آمار واقعی، مدیریت کاربران و نقش‌ها، وضعیت اشتراک‌ها، گردش کار تیکت‌ها، وضعیت چرخه عمر آگهی، تنظیمات عمومی، اتصال‌های پرداخت و پیامک، مدیریت اسلایدر و بنر، و گزارش تغییرات مدیران است. سه بنر اختصاصی در `public/banners` قرار دارند و محتوای آن‌ها از جدول `site_slides` و API زیر مدیریت می‌شود:

```text
GET                    /api/content/slides
GET|POST               /api/admin/slides
PATCH|DELETE            /api/admin/slides/:id
GET                     /api/admin/audits
PATCH                   /api/admin/listings/:token
PATCH                   /api/admin/subscriptions/:id
```

اسلایدر صفحه اصلی خودکار، واکنش‌گرا، دارای کنترل دستی و قابل فعال/غیرفعال‌کردن و مرتب‌سازی از پنل مدیریت است.

## چرخه عمر آگهی‌ها

هر آگهی با توکن یکتای دیوار در SQLite ذخیره می‌شود و `first_seen_at`، `last_seen_at`، آخرین زمان راستی‌آزمایی و تاریخچه قیمت آن حفظ می‌شود. تطبیق وضعیت فقط پس از خزش کامل و موفق همان شهر/دسته انجام می‌شود؛ جست‌وجوی فیلترشده یا خزش ناقص هیچ آگهی‌ای را غیرفعال نمی‌کند.

- آگهی مشاهده‌شده: `active` و شمارنده عدم مشاهده صفر می‌شود.
- غیبت از خزش کامل: ابتدا `stale` و پس از سه نوبت ناموفق `inactive` می‌شود.
- پاسخ قطعی ۴۰۴ یا ۴۱۰ از صفحه جزئیات دیوار: `removed` می‌شود.
- خطای شبکه، محدودیت نرخ یا قطع دیوار به‌عنوان حذف تلقی نمی‌شود.
- اگر آگهی دوباره ظاهر شود، خودکار به `active` برمی‌گردد.

آگهی‌های خارج‌شده از نتایج عمومی حذف می‌شوند ولی رکورد و تاریخچه آن‌ها برای تحلیل بازار در آرشیو باقی می‌ماند. وضعیت‌ها و تعداد دفعات عدم مشاهده در بخش آگهی‌های پنل مدیریت قابل مشاهده‌اند.

## مسیر اختصاصی مدیریت و داده آنلاین

ورود مدیریت از مسیر `/khodroto-admin` و با متغیرهای سروری `ADMIN_PHONE` و `ADMIN_PASSWORD` انجام می‌شود. راه‌اندازی اتصال مستقیم ایران، رله خصوصی برای Render و عیب‌یابی وضعیت واقعی collector در [ONLINE_SETUP.md](ONLINE_SETUP.md) توضیح داده شده است.

### اتصال مستقیم دیوار با سایت جهانی

برای اجرای frontend/backend روی میزبان جهانی و عبور فقط ترافیک جمع‌آوری از رله خصوصی ایران، راهنمای [GLOBAL_DIVAR_DEPLOYMENT.md](GLOBAL_DIVAR_DEPLOYMENT.md) و فایل‌های آماده `docker-compose.relay.yml`، `deploy/relay.Dockerfile` و `deploy/relay-nginx.conf` را ببینید. این معماری به «کنار» وابسته نیست.
